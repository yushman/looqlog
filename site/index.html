▪ looqlog

A timeline for your log file, without uploading it anywhere.

One binary. Point it at a file or pipe a stream into it, and a browser tab opens with a histogram timeline, filter chips, full-text and regex search over a table that stays smooth at any size. In file mode the log is read by the browser and never reaches the backend at all.

MIT One static binary Rust + WebAssembly No config, no server, no account
cargo install looqlog GitHub Quickstart

One command, then a browser tab

No config file, no daemon, no index to build first. The format is detected from the first lines and can be overridden if the guess is wrong.

# a file on disk — parsed in the browser, never sent to the backend
$ looqlog /var/log/app.log
  serving on http://127.0.0.1:7891

# a live stream — anything that writes to stdout
$ kubectl logs -f deploy/api | looqlog
$ docker logs -f web | looqlog
$ tail -F /var/log/syslog | looqlog

# pick the format yourself when detection guesses wrong
$ looqlog app.log then open #format=logfmt

What opens. Timeline on top, chips built from the fields that were actually found, table below — all of it over the same dataset, so narrowing one narrows the others.

Every number below came off a benchmark or a stopwatch on a real binary, and the command that produced it is recorded in the project's devlog — including the runs that went badly.

Where the time went

Filter, and the rest of the shape stays visible

Chips are built from the fields the parser actually found, with counts. Narrowing to level=ERROR redraws the timeline over a muted copy of the unfiltered data, so a filter that matched almost nothing reads as "filtered to nothing" rather than "no data" — and a burst you were looking for stops hiding under the noise.

1,428 lines of mixed service logs, narrowed to errors. The spike at 14:09 is an incident.

Multi-line events

A stack trace is one event, not sixty rows

Java stack traces, Python tracebacks and pretty-printed payloads are recognised as continuations of the entry above them and collapse into it. The timeline counts events rather than physical lines, so one exception is one bar and not a wall of them. A search that matches a frame in the middle of a trace surfaces the exception it belongs to, rather than the naked frame.

Row 983 carries eight lines. Recognition uses explicit frame markers, never indentation alone — on a 168,260-line Android bugreport that rule fires zero times across 134,960 lines of unprefixed dump text.

Formats it reads

JSON Lines, logfmt and plain text, auto-detected. Inside the plain-text path it also recognises leading timestamp shapes and reads what follows them: syslog, klog, Apache/CLF, Docker-wrapped stdout and Android logcat, including logcat's uid/pid/tid columns and tag, which become filterable fields rather than message noise.

A line it cannot parse is skipped and reported, with the line number and the reason. Entries produced plus lines skipped plus blank lines always equals the total line count — a log viewer that quietly loses lines is worse than no log viewer.

Quickstart

Install. cargo install looqlog, or grab a binary from Releases (Linux x86_64 static, macOS arm64 and x86_64). Nothing else to install — the UI is compiled into the binary.
Open something. looqlog app.log for a file, or pipe a stream into it. The address is printed; --open launches the browser for you.
Share the view, not the log. Filters, search text and the selected time range live in the URL fragment. Send someone the link and they land on the same view of their own copy — the fragment never leaves the browser.

Privacy, stated precisely

The two modes do not carry the same guarantee, and collapsing them into one slogan would be a lie in one direction.

File mode — never leaves the browser

The file is read through the browser's File API and parsed by WebAssembly in the tab. The backend never opens it, and no request carries its contents. Turn off the network after the page loads and everything still works.

Stdin mode — never leaves the machine

Lines travel from the CLI process to the browser over a localhost WebSocket in the clear, guarded by an origin check and a per-process token. That stops another page in your browser; it does not stop another process on the same machine.

Nothing phones home in either mode. There is no hosted service, no telemetry, no CDN at runtime, and no account.

Why not just use something else?

Use lnav if you live in the terminal — it is excellent, it has a decade of polish, and it never leaves your shell. looqlog exists because a histogram over time, a drag-to-select range and a filter panel are things a browser does better than a TUI, and because handing a colleague a URL is easier than handing them a keybinding.

Use Kibana or Grafana if you already run them. They win the moment you have more than one machine's logs. looqlog is for the file already on your disk and the stream already in your terminal — no ingestion, no index, no infrastructure to stand up before you can look at anything.

Do not use an online log viewer. Pasting production logs into a web form sends them to someone else's server. That is the specific thing this tool exists to make unnecessary.
