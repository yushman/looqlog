# looq

Single-binary CLI, который поднимает локальный web UI для просмотра лог-файла или
live-потока из stdin. Парсинг происходит в WebAssembly прямо в браузере — содержимое
логов не покидает машину.

[English version](README.md)

> **Статус: v0.1.0, MVP полностью реализован.** Сервер, CLI, парсер на стороне
> браузера (JSON Lines / logfmt / plain text, с авто-определением формата) и
> live-стриминг stdin работают end-to-end. В режиме файла парсер работает в Web
> Worker — большой файл не подвешивает страницу; в режиме stdin есть кольцевой буфер
> ограниченного размера, так что строки, выведенные до подключения браузера, не
> теряются, а медленный клиент никогда не блокирует производителя. Гистограмма на
> `uPlot` показывает количество записей по временным интервалам с выделением
> диапазона перетаскиванием мыши, а таблица с виртуальным скроллом рендерит только
> видимые строки независимо от размера датасета (50 000 записей скроллятся плавно).
> Выбор строки открывает детальный просмотр с полным сообщением и всеми
> извлечёнными полями. Фильтры-чипы, полнотекстовый/regex-поиск и состояние в URL
> сужают тот же датасет, что показывают timeline и таблица — см. раздел «Фильтры,
> поиск и шаринг вида» ниже. Обе панели корректно работают с живым потоком, который
> растёт и вытесняет старые записи, включая фильтры. CSP, проверка origin у
> WebSocket и токен на процесс закрывают дыру cross-tab hijacking на `/ws` (см.
> «Безопасность»); есть лимиты на размер файла, отдельные сообщения об ошибках и
> светлая/тёмная тема (см. разделы ниже). Оформление минимальное, не отполировано.

## Зачем

У `grep`/`awk`/`less` нет timeline и структуры. Kibana/Grafana требуют инфраструктуры.
Онлайн-вьюеры логов отправляют данные на чужой сервер. looq — один бинарь:
указываешь файл или пайпишь stdin, получаешь UI с поиском, фильтрами и timeline прямо
в своём браузере — privacy-first, без конфигурации.

## Установка

```bash
cargo install looq   # запланировано — ещё не опубликовано
```

Для сборки из исходников нужен только Rust toolchain — собранный фронтенд
(`core.wasm` + JS-обвязка) закоммичен в репозиторий, поэтому `cargo build`/`cargo
install` никогда не вызывают Node.js или `wasm-pack` (см.
[ADR-0008](docs/adr/0008-vendored-frontend-artifacts.md)):

```bash
git clone https://github.com/looq-dev/looq
cd looq
cargo build --release
./target/release/looq --version
```

Готовый бинарь появится в Releases после релиза v0.1.0. Целевая платформа релиза —
Linux x86_64 как минимум (TDR §5); размеры, зафиксированные и для неё, и для
платформы, на которой реально собирался релизный бинарь в этом репозитории, — в
записи `release-hardening` в `docs/devlog.md`.

### Разработка фронтенда

Директория `web/` — это Vite + TypeScript проект; он нужен только для изменения
фронтенда, а не для сборки или установки самого `looq` (тот путь — чисто Rust, см.
выше). `scripts/build-frontend.sh` собирает его (через `wasm-pack` + `npm`) и
кладёт результат в `crates/looq/assets/` — именно это и попадает в бинарь:

```bash
./scripts/build-frontend.sh   # нужны Node.js + npm + wasm-pack
cargo build --release
```

## Использование

У looq два режима запуска, и — это важно — они дают разные privacy-гарантии. См.
[ADR-0002](docs/adr/0002-wasm-browser-parsing-file-mode.md) и TDR §12 для полного
обоснования.

### Режим файла

```bash
looq app.log
```

Это запускает сервер и печатает `app.log` как **подсказку** — процесс не открывает и
не читает файл сам, и не может: ни один browser API не позволяет странице
автоматически открыть путь, выбранный сервером (см.
[ADR-0007](docs/adr/0007-argv-path-is-a-hint-not-an-auto-loaded-file.md)). Откройте
напечатанный URL, затем выберите `app.log` сами через file picker на странице или
перетащите его на drop-зону. Файл читается и парсится полностью в браузере; `looq`
никогда не видит его содержимое — это можно проверить самостоятельно: панель Network
в DevTools остаётся пустой после загрузки страницы, и парсинг продолжает работать при
отключённой сети.

### Режим stdin

```bash
myapp | looq
# или явно:
tail -f /var/log/app.log | looq --stdin
```

Строки из stdin передаются подключённым браузерам по localhost WebSocket без
аутентификации. Это **более слабая** гарантия, чем режим файла: данные пересекают
границу процессов (CLI → браузер), хотя и не покидают машину — индикатор режима на
странице явно об этом говорит, другими словами, чем "never leaves the browser" в
режиме файла (TDR §12).

Backend хранит кольцевой буфер ограниченного размера (`--max-lines`, по умолчанию
100 000), заполняемый с момента старта процесса независимо от того, подключён ли
браузер — так `myapp | looq`, за которым через несколько секунд следует открытие
браузера, всё равно покажет всё, что `myapp` уже вывел: новое или переподключённое
соединение получает snapshot буфера, затем переходит в live-режим. Медленный или
отсутствующий браузер никогда не блокирует производителя — при устойчивом
backpressure старые недоставленные сообщения отбрасываются, а страница показывает
видимый маркер разрыва с числом потерянных строк, а не молча укороченный хвост.
Страница также показывает индикатор live/connecting/ended/disconnected, счётчик
строк/сек, автоскролл, который приостанавливается при прокрутке вверх, и
переподключение с задержкой при обрыве связи.

### Остальные флаги

```bash
looq --port 9000 app.log     # выбрать порт (0 = случайный свободный)
looq --open app.log          # автооткрытие браузера по готовности
looq --host 0.0.0.0 app.log  # доступ за пределами localhost — печатает обязательное предупреждение
```

Полный список флагов — `looq --help` (`--port`, `--host`, `--open`, `--no-browser`,
`--stdin`, `--max-lines`).

## Фильтры, поиск и шаринг вида

Фильтры, поиск и активный временной диапазон сужают *один и тот же* датасет —
таблица, timeline и все счётчики на экране согласованы, потому что все читают из
одного предиката.

**Фильтры.** Для каждого поля, которое нашёл парсер (`level` и остальные поля из
логов), в левой панели появляется своя сворачиваемая секция с реальными значениями и
их счётчиками. Клик по значению активирует его. **Значения одного поля объединяются
через ИЛИ** (выбор `ERROR` и `WARN` покажет оба уровня), **разные поля объединяются
через И** (добавление `service=api` сузит до записей, соответствующих *обоим*
условиям). Поле со слишком большим числом различных значений (за пределами cap
парсера по кардинальности, или просто слишком много, чтобы их перечислять) вместо
списка предлагает текстовое поле — введите значение и нажмите Add.

**Поиск.** Строка поиска ищет по тексту сообщения и значениям полей, без учёта
регистра, по подстроке по умолчанию. Префикс `re:` включает регулярное выражение,
применяемое как есть (без неявной нечувствительности к регистру) — например,
`re:^ERROR.*timeout`. Невалидное регулярное выражение показывает ошибку прямо в
интерфейсе и оставляет прежний результат на экране вместо того, чтобы опустошить
таблицу — так «плохой regex» и «валидный поиск без совпадений» никогда не выглядят
одинаково. Чтобы искать буквальный текст, начинающийся с `re:`, экранируйте его
обратным слэшем: `\re:something`. Ввод `field=value` для существующего поля (например,
`service=api`) превращается в чип вместо поиска по буквальному тексту — так что клик
по чипу и ввод его `field=value`-эквивалента дают одинаковый результат. Escape
очищает строку поиска, не трогая активные чипы.

**Шаринг через URL.** Фильтры, поиск, выбранный временной диапазон, переопределение
формата и таймзоны — всё это раунд-трипится через URL hash
(`#filter=...&q=...&range=...`), записываемый через небольшую паузу после последнего
изменения (не на каждое нажатие клавиши, чтобы не засорять историю браузера) и
применяемый автоматически при открытии той же ссылки и выборе того же файла.
**Hash содержит текст поиска и значения фильтров — реальные фрагменты вашего лога** —
поэтому ссылка, скопированная через кнопку «Copy shareable link», и предупреждение,
которое показывается в этот момент, говорят правду: не вставляйте её туда, куда
содержимому лога попадать не следует. URL с нераспознанной или некорректной частью
применяет всё, что может, и сообщает, что именно не применилось, вместо того чтобы
молча отбросить всё целиком.

**Live-потоки.** Всё вышеописанное работает и для `myapp | looq` — фильтры и поиск
применяются к каждой строке по мере поступления, счётчик записей отличает совпавшие
от общего числа полученных, а изменение фильтра посреди потока немедленно
переоценивает все сохранённые строки, без переподключения.

## Безопасность

Сервер отправляет `Content-Security-Policy: default-src 'self'` на каждый ответ
(`script-src` также разрешает `'wasm-unsafe-eval'` для компиляции WASM с того же
origin, а `style-src` разрешает `'unsafe-inline'` — таблица с виртуальным скроллом
позиционирует строки инлайн-стилями; обе добавки осознанные и узкие, а не ослабление
политики по умолчанию).

`/ws` (транспорт live-tail в режиме stdin) защищён двумя способами:

- **Проверка Origin.** Апгрейд WebSocket, у которого заголовок `Origin` не совпадает
  с `Host` самого запроса, отклоняется с `403` до завершения handshake и до того, как
  может уйти хоть один байт stdin.
- **Токен на процесс в handshake.** Отдаваемая страница содержит случайный токен,
  сгенерированный один раз при старте `looq`. Собственный JS страницы отправляет его
  первым сообщением при каждом подключении к `/ws` (никогда не в URL или query
  string — чтобы не попасть в историю шелла или лог прокси); соединение, не
  предъявившее токен за несколько секунд, закрывается без отправки каких-либо данных.

**Что это защищает — прямым текстом, чтобы не приняли за большее:** страница с
другого origin — например, вредоносная вкладка в том же браузере — не может прочитать
токен (она не может получить HTML вашей страницы `looq` кросс-origin) и поэтому не
может открыть поток stdin. Это **не** защищает от другого процесса на той же машине,
который может просто сам запросить страницу так же, как это сделал бы браузер. Это
**не** добавляет никакой защиты для `--host 0.0.0.0` или любого другого небиндинга на
loopback — кто угодно, кто может достучаться до этого хоста и порта, может получить
страницу, а затем и токен, точно так же, как легитимная вкладка браузера. Эта дыра
принята, а не закрыта ([ADR-0003](docs/adr/0003-bind-127-0-0-1-by-default.md)):
биндинг за пределами `127.0.0.1` всегда печатает обязательное предупреждение,
называющее ровно эту проблему.

## Лимиты на размер файла

Парсинг держит каждую запись и её индекс в памяти браузера, поэтому есть
практический потолок значительно ниже номинальных 4 ГБ, которые предполагает
32-битное адресное пространство. Измерено (не угадано — см. запись
`release-hardening` в `docs/devlog.md`): рабочий набор на стороне браузера (`entries`
+ временной индекс) растёт на удивление стабильно — примерно 3.4x от сырого размера
файла. Отсюда два порога:

- **Выше ~50 МБ** открытие файла показывает предупреждение (продолжить/отменить) —
  и время парсинга, и потребление памяти заметно растут после этой точки.
- **Выше 400 МБ** looq вообще отказывается начинать парсинг и объясняет почему, а не
  запускает парсинг, который может упасть на середине с непонятной ошибкой нехватки
  памяти. Разделите файл (например, по временному диапазону) или отфильтруйте его
  перед открытием.

## Состояния ошибок

У каждого сбоя — своё конкретное, не исчезающее само по себе сообщение вместо
пустого экрана, бесконечного спиннера или ошибки только в консоли: пустой файл,
файл, похожий на бинарный (NUL-байты в начале — с возможностью «всё равно
продолжить», потому что лог с одним случайным NUL-байтом — реальный, пусть и редкий
случай), файл, который браузер не смог прочитать, WASM-модуль, который не
загрузился, и формат, давший ноль записей (читается отдельно и от пустого файла, и
от фильтра, не давшего совпадений). Ошибки остаются на экране, пока их не закроют
или пока не откроется другой файл успешно — никогда не исчезающий сам по себе
toast — а неудачное открытие второго файла никогда не стирает то, что уже загрузил
первый.

## Тема

Светлая и тёмная, по умолчанию следует настройке ОС. Переключатель в верхней панели
циклически переключает Auto → Light → Dark → Auto; явный выбор запоминается
(`localStorage`) между перезагрузками на одной машине. Нигде не используются внешние
шрифты, стили или изображения, поэтому обе темы полностью рендерятся при отключённой
сети.

## Известные ограничения

- **Именованные таймзоны не поддержаны** — только UTC и фиксированные offset'ы.
  Timestamp, записанный в локальном времени `Europe/Belgrade` без явного offset,
  читается как UTC. Полная база IANA-таймзон (`chrono-tz`) почти наверняка пробила бы
  бюджет размера `core.wasm` — так же, как это сделал `regex` (см. `docs/devlog.md`).
- **Одна физическая строка = одна запись.** Многострочные payload'ы (например,
  Java stack trace) становятся N отдельными строками таблицы, а не одной
  агрегированной записью — осознанное сужение MVP-скоупа, а не баг парсера.
- **Вложенные JSON-объекты/массивы хранятся как сырой текст**, не разворачиваются в
  точечные ключи (`http.status`) — показываются как есть в детальном просмотре, не
  фильтруются по вложенным полям.
- **Нет gzip/zstd-декомпрессии, слияния нескольких файлов, экспорта** — всё это
  осознанно вне MVP-скоупа (`docs/PRD.md` §8).
